# 后端开发规范

后端任务使用 [sql-studio-backend skill](../.agents/skills/sql-studio-backend/SKILL.md)，先读[架构](BACKEND_ARCHITECTURE.md)、[包索引](../sql-studio-backend/internal/README.md) 和目标模块 README；用户最新要求优先。

## 模块化单体

保留单个 Go module、启动入口、进程与 HTTP 服务，业务按连接管理、数据库对象、SQL 查询等功能独立封装，采用类似独立服务的职责和契约边界。模块在进程内调用，不引入服务发现、内部 HTTP/RPC、网关、消息队列或多套部署配置。

`internal/modules/<feature>` 包含本功能的业务入口、消费接口、规则及测试，只导出外部实际需要的构造器、方法、错误和类型。模块之间不直接导入，不共享可变内部字段；跨模块装配与协调放 app。接口由消费模块定义，只要求实际需要的方法，具体实现从构造器注入。

HTTP 只负责解码、校验传输边界、调用模块及编码响应；app 只装配实现、初始化与管理生命周期；入口 main.go 只加载配置、创建 app 和处理退出。不得重新把所有功能堆回一个总 service，或保留旧路径转发壳。

## 功能、文档与类型

每个实际 Go 包有同目录 README.md 与包注释 doc.go，源码和测试按功能职责分文件；保留 Go 原生命名、gofmt 与 package 规则，不套前端 index.ts 规则，不为每个局部方法建立空包。

README 说明职责、公开入口、参数类型与默认值、返回值、错误、调用方式、超时/取消、并发与缓存归属。移动模块同步调用方、父级索引、API 说明及架构测试。

复用契约使用明确 struct、命名类型和 const；共享 model 仅放确实跨边界复用的数据契约。模块私有类型及常量留在本模块，不为复用创建无关大杂烩。使用最小接口和 errors.Is/As 处理可判定错误；HTTP/存储输入必须做运行时校验，不用任意 map 或无约束 any 代替已知业务类型。

## 引擎、存储与请求边界

MySQL 的连接、TLS、SQL 识别、元数据与执行放 internal/mysql；HTTP/业务模块不导入驱动、拼数据库协议 SQL 或读取环境变量。PostgreSQL 专属实现放 internal/postgresql，internal/database 只负责分派，app 注册实际实现；不预建未支持引擎的空实现。连接配置与 AES-GCM 落盘由 internal/connection 负责，环境变量由 internal/config 读取。

context 从 HTTP 一直传到驱动，不丢失取消和超时。app 创建共享资源并确定生命周期，SQL 并发预算属于 query 模块，不能每次请求重建或交由 handler 管理。每次操作携带明确连接 ID 与对象范围，保留默认只读、单语句、行数/字节限制、精确数值文本和游标/连接释放行为。

密码不进入日志或 API 返回；编辑空密码保留旧密码，密钥丢失不得覆盖已有数据。取消不能被描述为事务已回滚。全局配置只使用当前格式，不提供旧格式读取、字段回退或迁移；不修改实际业务数据或凭据文件。

## 原生命令与清理

从 `sql-studio-backend` 目录直接运行，不用启动/停止/检查包装脚本，也不提前增加容器或部署配置：

```sh
go run main.go
```

默认终端输出日志，Ctrl+C 退出；不生成后台 PID 或将日志重定向进仓库。现有运行参数按需使用环境变量，不删除程序必需配置、go.mod/go.sum 或加密数据目录。脚本自动化和部署配置等以后有实际需求再添加。

验证使用 `gofmt -w .`、`gofmt -l .`、`go test -count=1 ./...`、`go vet ./...`、`go build ./...`。测试与实现放包内或 tests，保留有效回归测试，不用临时脚本取代测试。真实数据库集成须显式启用，只操作随机临时库；普通重构使用测试替身与临时目录。临时验证产物验证后清理，只删除已核对归属的日志、脚本和生成文件。
