# SQL Studio 全局静态检查

先读 [SQL Studio 项目技能](../sql-studio/SKILL.md)，按涉及范围读取 [前端技能](../sql-studio-frontend/SKILL.md)、[后端技能](../sql-studio-backend/SKILL.md) 和实际模块 README。全局检查覆盖前端、后端、Electron、本地测试库配置及配套文档。

## 检查与修复

1. **代码规范。** 核对模块入口、依赖方向、类型契约、格式与静态告警。查看当前工作区差异，保留用户已有修改，只格式化本轮改动文件。
2. **样式规范。** 按 [前端开发规范](../../../docs/FRONTEND_STANDARDS.md) 检查共用组件、主题令牌、尺寸、表单布局、窄屏伸缩和焦点状态。结合亮暗主题核对共用样式的使用方。
3. **功能完整性。** 沿真实入口核对界面操作、服务调用、API 注册、引擎分派和实现是否衔接。按各引擎已声明的能力检查禁用状态、错误反馈、范围切换和取消，区分可修复缺陷与已记录的支持边界。
4. **修复并更新文档。** 自行修复可从源码确认的问题，复查同类使用方。同步受影响的模块 README、父级索引、用户文档和 API 契约，在原位置更新过期说明，核对本地链接。

## 静态验证与交付

- 前端可使用已安装的 TypeScript 无输出类型检查、Oxlint、SCSS 解析及只读取源文件的结构检查。分别执行所需检查，避免合集命令带入运行时测试。
- 后端可执行 `go vet`、Go 格式检查及只解析源码的分层检查。Electron 可使用 `node --check` 校验脚本，Compose 可使用 `docker compose config --quiet` 检查配置和兼容版本。
- 全程只做静态检查。应用、浏览器及容器的启动和调试，运行时功能测试及真实数据库验证由用户处理。
- 复查最终差异。交付时列出已修复的问题、更新的文档、实际通过的静态检查和仍待验证的功能，遵循项目技能的版本与提交日志约定。
