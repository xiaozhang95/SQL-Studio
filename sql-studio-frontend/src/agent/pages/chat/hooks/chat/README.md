# 会话生命周期

useChat(workspace)管理Form、SSE、历史列表与创建/删除/重命名。初始化先ensureHistory，空列表由后端原子创建默认会话，优先恢复activeId，否则选中首条，再只读加载事件。createNew立即创建、刷新索引并选中，不等待首条消息。删除当前会话选中剩余首条，删除最后一条自动确保新的默认会话；删除其他会话保留当前内容和草稿。

renameHistory只替换索引信息，不改变当前消息/草稿/展开状态；服务端保存手动命名。mutation ref阻止重复点击，historyVersion丢弃跨变更的旧列表响应。管理错误保留已有内容；创建/删除/重命名期间禁止重复变更，选择会话期间允许改选并取消旧读取；卸载取消流和初始化请求，StrictMode不会重复创建默认项。

refreshHistory只读取并更新索引，不创建默认会话、不请求其他会话正文、不改变activeId、正文、草稿和展开状态。当前会话缺失时保留已知的当前列表项与内容并显示提示；再次刷新恢复该项后仅清除此提示。重叠刷新只接受最新一次响应，旧成功/失败不能覆盖新列表、错误或加载状态；用户改选或管理会话后丢弃旧刷新。删除非当前会话同样保留当前项，即使返回列表暂时缺失它；只有初始化、明确新建或删除当前会话才自动激活目标。

恢复不执行模型或SQL；实时SSE经applyEvent折叠，历史经restoreEvents分批还原，取消保留已输出片段。草稿与展开状态交给workspace保存，历史折叠抽屉由historyOpen控制。

editQuestion(text)将已有问题回填当前输入框、同步本机草稿并聚焦；执行或管理会话中不回填。由用户修改并再次发送，不改写原问题。

写入逐次确认：execute_write通过write_confirmation SSE事件暂停，携带approvalId/connection/database/objects/sql。POST /api/agent/write-confirmation提交allow，确认ID不可重复使用；未确认、取消、超时、断开不执行，取消结束本轮。服务端生成明细并绑定本次目标/SQL，不接收前端替换SQL。确认独立等待最多5分钟，等待期间暂停本轮执行计时；恢复历史不重新显示已过期确认卡片。模式提示不替代逐次确认。

useChat.confirmWrite公开写入或继续确认的明细、提交状态和错误。decideConfirmation负责提交决策，输入超长确认选择返回编辑时恢复原文，页面将其组合为最后一轮回复下方的确认卡片；等待时status显示“等待确认数据库操作”，不再发起执行确认弹窗。

历史选择采用与SQL页相同的按需加载边界：先更新活动会话和加载占位，立即释放旧消息/用量，不缓存非活动会话全文；仅读取所选会话。连续选择取消旧请求及事件还原，提交前核对控制器、当前会话与挂载状态；卸载取消。每256个事件分批校验和还原，完成后一次提交，不显示部分记录。失败保留目标选中，提供重试且允许切到其他会话，加载/失败时禁止发送和回填问题；不把空占位保存成会话内容。重复选择当前项不重读，显式重试重新读取。选择期间仍允许选择其他会话，新建/删除/重命名暂停；实际模型执行仍锁定切换。恢复失败重试保留当前草稿/展开状态。
